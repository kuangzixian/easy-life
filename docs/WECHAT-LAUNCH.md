# 第一次发布微信小程序

核验日期：2026-09-30。本文给出实际操作顺序；账号可用能力、类目、资质、认证费用和审核结果，以提交当天的微信公众平台后台为准。代码完成、体验版可用、审核通过、正式发布是四个不同状态。

本项目首版定位为生活知识的阅读与检索工具：顺序阅读、输入问题查找已有资料、随机建议卡片、本地收藏与阅读进度。检索结果来自收录内容，不是大模型实时生成的回答。首版不需要自建服务器、用户登录、付费云资源或模型密钥。

## 先做这三件事

1. **注册自己的小程序账号。** 打开 [微信公众平台](https://mp.weixin.qq.com/)，选择注册“小程序”，按真实情况选个人或其他主体，完成邮箱、实名与管理员绑定。不要用公众号的 AppID。管理员扫码、短信验证、人脸或证件核验需要账号所有者本人完成。
2. **拿到 AppID，并确认服务类目。** 登录后台，在“开发管理 / 开发设置”等入口找到 AppID；菜单名称可能调整。把 AppID 用于本地开发者工具配置即可，不需要提供 AppSecret、账号密码或身份证照片。优先核对“工具 → 信息查询”是否覆盖本项目的实际服务，再看内容阅读是否涉及其他类目。
3. **确定公开展示的信息。** 确认最终名称、图标、简介，以及用于接收纠错和侵权反馈的公开联系渠道。不要把个人身份证、手机号、住址、备案核验材料或任何密钥提交到公开 GitHub 仓库。

[微信官方入门文档](https://developers.weixin.qq.com/miniprogram/dev/framework/quickstart/getstart.html)说明了账号、AppID、开发者工具和手机预览的关系；测试号可以帮助开始开发，但不代表获得正式小程序的发布资格。

## 个人主体与类目怎么判断

截至核验日，[微信官方服务类目表](https://developers.weixin.qq.com/miniprogram/product/material.html)列有个人主体的“工具 → 信息查询”。这是可优先核对的候选类目，不是本项目已获准使用的结论。实际内容和功能必须完整披露，不能只改名称、隐藏页面或把业务写成“工具”来规避资质。

尤其需要区分：个人“健康管理”范围是身高、体重等管理记录，不能据此推断健康指南或医疗咨询都允许；执业法律服务有对应资质要求；金融服务、出版物阅读等也有各自的准入规则。生活资料中包含相关话题，不自动等于经营这些服务，也不自动免除类目审核。请把体验版内容与真实功能交给平台判断。

首发内容检查应逐条完成：保留原文来源及版本；核对授权许可与第三方材料权利；标明经验性建议和时效信息；避免把健康、法律、金融资料包装成诊断、个案法律意见或投资指令；随机卡片保留必要的条件和上下文。来源署名和提示文字不能代替内容权利或所需资质。

若个人后台没有覆盖实际服务的类目，记录平台反馈，明确缩小产品范围或改用具备相应资格的主体。不要承诺“个人一定能过审”，也不要为了试错盲目付费认证；需要认证及费用时，以账号后台当次流程为准。

## 导入、预览与体验版

1. 从[官方页面](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)安装微信开发者工具，用管理员或已添加为开发者的微信扫码登录。
2. 先在本机执行 `npm run configure -- 真实AppID`，脚本只写入被 Git 忽略的 `project.private.config.json`，公共 `project.config.json` 保留游客占位值。再选择“导入项目”，导入本仓库根目录；微信开发者工具会优先使用私有配置中的 AppID。首版不需要开通云开发。详见仓库 README 和[官方项目配置说明](https://developers.weixin.qq.com/miniprogram/dev/devtools/projectconfig.html)。
3. 点击“编译”，检查目录、搜索、卡片、收藏与关于页面。模拟器正常后点击“预览”，用有权限的微信扫码在手机检查。
4. 在后台“成员管理”添加需要测试的人；开发权限与体验权限是不同权限。
5. 在开发者工具点击“上传”，填入版本号和说明。在后台“版本管理”的开发版本中将上传版本设为体验版，把体验码提供给已添加的体验成员。

上传开发版本不会直接对公众发布；体验版也不是正式版。正式路径是预览、上传、提交审核、审核通过后发布，详见[微信官方协同与发布文档](https://developers.weixin.qq.com/miniprogram/dev/framework/quickstart/release.html)。

## 备案与提审

面向境内公众提供互联网信息服务的小程序需要履行备案手续。没有自建服务器不等于不需要小程序备案。应通过微信公众平台的“小程序备案”入口提交资料，并由账号所有者本人完成验证。需要哪些证件、联系方式、承诺文件及核验动作，以主体所在地和后台要求为准。

[工信部 105 号通知](https://www.miit.gov.cn/zwgk/zcwj/wjfb/tz/art/2023/art_920db564162e4312916a01bed6540ad8.html)规定先履行备案手续再开展业务，并要求展示备案编号、按要求链接查询系统。通知中的二十个工作日指省级通信管理局收到齐全、准确材料后的办理口径，不是从注册到上线的总工期承诺。备案通过后，将真实编号填入产品，核对展示和查询入口；不能生成或借用备案号。

提交代码审核前，在后台逐项核对名称、简介、图标、服务类目、资质、备案状态和用户隐私保护指引。按实际行为声明本地收藏、阅读进度、搜索输入以及所用接口；没有采集的内容不要写成“已收集”。具体入口与提审版本的隐私声明更新方法见[微信官方隐私指引](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/)。

后台可能要求填写测试路径、服务说明或补充材料。首版无账号登录时，明确写“无需登录”，提供可操作的页面路径和例子。收到驳回应根据具体原因修正内容、功能或材料，再提交同一实际版本；审核通过后仍需在后台执行“发布”。

## 可直接整理到后台的产品资料

| 项目 | 草稿或待填写内容 |
| --- | --- |
| 小程序名称 | 待所有者确认；后台检查名称可用性和命名规范 |
| 简介草稿 | 将生活知识整理成易读指南，支持目录阅读、问题检索、随机建议与本地收藏。 |
| 功能说明草稿 | 输入问题后匹配已收录资料，展示相关内容与来源；支持按目录顺序阅读和切换随机建议卡片。无需登录。 |
| 候选服务类目 | 工具 → 信息查询；以实际内容、主体能力和平台审核为准 |
| AppID | 仅在本机 `project.private.config.json` 填写真实 AppID，不提交 GitHub |
| 运营主体与联系渠道 | 待填写适合公开展示的名称及纠错/侵权反馈渠道 |
| 备案编号 | 备案通过后填写真实编号，并完成产品展示与查询入口 |
| 内容来源 | HowToLiveBetter；同时附来源地址、许可证、导入版本和本项目的整理说明 |
| 审核测试路径 | 首页进入指南 → 打开文章；进入搜索 → 输入“如何改善睡眠”；进入卡片 → 切换及收藏；进入收藏 → 查看已保存内容 |
| 版本号及说明 | 使用本次实际上传版本；说明新增内容和功能，不填尚未实现的服务 |

文案草稿应与最终页面、代码行为和已核实的内容授权一致后再使用。

## 发布前验收

- [ ] 内容来源、许可证与第三方引用已检查，未把开放访问误当作允许转载。
- [ ] 从目录第一篇可以开始阅读，上一篇、下一篇与继续阅读均正确。
- [ ] 搜索能匹配示例问题；无结果时有明确提示；结果能打开对应文章并查看来源。
- [ ] 随机卡片可切换，卡片文字完整可读，收藏与取消收藏即时一致。
- [ ] 退出再进入后，本地收藏与进度仍在；清除本地数据后界面恢复合理状态。
- [ ] 至少在一台 iPhone 和一台 Android 真机检查安全区、长文滚动、中文输入、大字体、切后台恢复和分享入口。
- [ ] 断网时已下载的本地内容可用；没有误导性的实时信息或 AI 生成承诺。
- [ ] 关于页的名称、公开联系渠道、来源和备案信息为最终值，页面没有待填占位。
- [ ] 开发者工具上传通过，真机体验无阻断错误；审核与隐私声明反映同一个实际版本。
- [ ] 备案完成、代码审核通过、已执行发布；普通微信账号从正式入口可访问。

浏览器展示或自动化逻辑测试不能替代微信开发者工具编译和真机测试。上线状态应同时记录正式版本号、发布时间与普通账号的访问结果。

## 以后加入生成式 AI 时

本地资料检索与生成式 AI 问答是两种实现。后者需要单独设计后端、模型调用、内容审核、来源约束、隐私处理、费用上限和异常处理，密钥只能放在服务端。

截至核验日，微信官方类目表中的“深度合成 → AI问答”位于非个人主体部分，个人类目表未列出该项。自研技术与调用第三方技术有不同材料要求；第三方路径列有技术主体的算法备案及双方合作协议。不能把“调用了已有备案模型”理解成自己的应用自动具备所有上线条件，也不能承诺当前个人账号可以直接开通。

对境内公众提供生成内容需进一步核对[《生成式人工智能服务管理暂行办法》](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)的适用要求，以及[生成合成内容标识规定](https://www.cac.gov.cn/2025-03/14/c_1743654685896173.htm)对界面、复制/导出和文件元数据的要求。应在接入前核对主体和后台材料，明确服务提供方与运营方各自需要完成的工作，再安排实现与提审。

## 开发上的几个边界

- 当前[官方分包限制](https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages.html)：主包和单个分包各不超过 2M，总分包不超过 30M；服务商代开发为 20M。最终以开发者工具实际打包结果为准；不要只看源码目录体积。
- 原生小程序的逻辑层不是浏览器，也不是 Node.js，不能直接依赖 DOM、BOM 或任意 npm 包；详见[官方运行环境说明](https://developers.weixin.qq.com/miniprogram/dev/framework/quickstart/)。
- 若以后加入服务器、外部图片、统计、登录或模型接口，需重新检查网络域名配置、隐私声明、内容安全、预算和真机表现，不能直接沿用首版“全部本地”的描述。
